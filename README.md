## 现场操作

1. 首次登录后台，复制「活动固定入口」里的现场海报链接到 iPad 并收藏。末尾的 `#speaker=…` 是该活动的播报权限，不是管理员口令，只供自己的设备使用。
2. 以后打开收藏的同一个链接，点一次「开启自动播报并试听」。听到云健确认音，右下角显示「播报已连接」后即可使用。
3. 这张海报本身播报，不用另开监听页。保持前台、屏幕不锁定，关闭静音并调高媒体音量。iPadOS 不保证切 App 或锁屏后的网页网络和音频运行。
4. 只在一页开启播报。关掉或刷新旧页后，新页最多等待 30 秒自动接替。
5. 结束后登录后台，按日期/活动/场次看记录并导出 CSV。到不同岩馆可「开始新场次」；入口不用换，历史数据保留。

## 两种码

- **网页互动码（相机 / 微信 / 支付宝）**：进入网页 → 服务器确认保存 → 尝试打开小红书；在线 iPad 按顺序播报。只有收到服务端确认才显示「扫码已记录」。仍须在实际手机与现场网络上验证微信、支付宝兼容性。
- **小红书原生个人主页码**：后台上传从小红书 App 保存的完整原图（PNG/JPG/WebP，≤512 KB），海报切换「小红书扫一扫」。直接进入小红书，不经过我们的网页，**不能自动计数或播报**。未上传时此入口禁用，还需本人实扫验收。
- 扫码不等于新增关注。「尝试打开主页」含自动跳转，也不代表 App 成功打开。匿名访客按浏览器估算；换浏览器、清除数据可能重复计人。
- 要把小红书 App 原生扫码、自动播报和平台内互动联在一起，需要另走经平台审核的小程序方案，不能靠改普通网页保证实现。

## 可靠性

弃用 ntfy 匿名频道作为配置与记录存储。活动、场次、匿名扫码及播放结果写入 CloudBase 文档数据库，没有应用层 TTL；浏览器仅保存设备偏好、匿名标识与待补发回执。

- 事务和唯一索引确保同一个 nonce 不重复计数；使用服务器时间、递增游标分页，不反复拉全部历史。
- 每次开启从当前游标开始，不重播历史。短暂断网恢复时两分钟以内扫码可补播，超过两分钟只留记录。
- 播放失败持续提示，需点重新允许声音；不被正常连接状态掩盖。固定文案用随站部署的云健 MP3，不悄悄回退系统朗读。
- 单设备租约；网络错误退避，联网/回前台自动重连。
- 二维码组件本地随站部署，不依赖外部 CDN。
- 管理接口认证，设备凭据仅限对应活动的简化播报队列与回执。岩友二维码无任何管理/播报凭据。

## 开发与部署

Node ≥22.13，设置至少24字符随机 `ADMIN_TOKEN` 后 `npm start`；本地 SQLite 在 `server/data/`。本地联调将 `runtime-config.js` 的 `apiBase` 留空；发布时填写真实 API。不要通过 file:// 打开。

`npm test`：临时 SQLite 测试覆盖跨年与重启持久化、并发去重、权限、租约、增量游标、回执、日期/场次筛选、CSV、原生码与 CORS。

`node tests/cloud-smoke.js <专用测试活动ID>`：显式公网测试，仅限名为「联调测试（非现场数据）」的隔离活动。读私有部署配置，不打印密钥。不以人工 ack 冒充实际音频验证。

生产必须 `STORAGE_DRIVER=cloudbase`，不能用云函数临时磁盘。安装 `server/package.json` 的 SDK；SCF 入口 `index.main`，Nodejs20.19。首次初始化六个 `dadi_*` 集合；`dadi_scans` 建唯一复合索引 `{eventId:1,id:1}`。HTTP 网关 /api 指向函数，适配器处理网关剥离前缀。

部署配置只在本机 `.deployment/cloudbaserc.json`，不要发布此目录、数据库、node_modules 或密钥。升级时保持 `SPEAKER_TOKEN_SECRET` 不变，收藏链接才能持续有效。服务端 SDK 当前 npm audit 报告 5 项依赖告警（axios、lodash 相关）；本应用不接受任意网络目标、查询键或数据库更新表达式，后续升级 SDK 时应复查依赖。不要未经测试直接运行 audit fix --force。
